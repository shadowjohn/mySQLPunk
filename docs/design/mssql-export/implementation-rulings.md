# MSSQL export implementation rulings

These decisions resolve implementation details within the approved design. Listed in decision order, including costs and validation boundaries. Verification outcomes are recorded separately in verification.md.

1. Use a CLI worktree for this repository after the native tool failed resolving the explicitly supplied repository commit — the app tool targeted a different repository and could not create this checkout — cost if wrong: worktree attachment/cleanup must be managed through Git, not the app artifact catalog. Main checkout and untracked user files stay unchanged; .git/info/exclude ignores .worktrees/.

2. Interpret stale-overwrite protection as serialized participating jobs plus a final full consent-stamp comparison; do not claim atomic compare-and-swap against uncooperative external writers — File.Replace has no expected-identity parameter, and holding a deny-delete handle also prevents replacement — cost if wrong: an external rename in the final check/replace interval may displace a newer version, which must remain recoverable rather than silently deleted. Use a unique recovery path for every overwrite and surface ambiguous/partial replacement outcomes; recommend a new filename where exclusive destination ownership is unavailable. Document this limit and test the race deterministically, not just via random stress.

3. On partial File.Replace failure, preserving verified prior bytes at an explicitly reported recovery pathname satisfies recoverability; do not universally assert preservation at the original pathname — Windows documents partial name changes on replacement errors — cost if wrong: a user may need manual recovery from the reported path. Never blindly roll back over a newly appeared destination, and preserve uncertain survivors.

4. Preserve varchar/text source bytes via direct binary assignment into an exact-source-collated target/staging column, instead of CONVERT(varchar(max), hex) followed by COLLATE — the dedicated SQL Server probe proved the proposed cast loses bytes under differing code pages — cost if wrong: collation-specific roundtrips could corrupt values; retain byte/hash fixtures across code pages and UTF8. Task 4/5 briefs carry the measured correction.

5. Apply the approved design's identity contract (seed/increment, preserved values, collision-free subsequent inserts), not exact restoration of the source allocation counter — Task 3 plan wording mentioned last_value more strongly than the design, and native counter allocation is mutable outside the data snapshot — cost if wrong: post-restore generated values can differ from source allocation gaps/reseed history. Task 3 must verify fresh empty and positive/negative arbitrary-order restoration plus safe next inserts; do not add last_value to the definition fingerprint. Native probe in fixture-prep-report.md passed both directions. Final exporter/sqlcmd evidence remains required.

6. Run Task4 values concurrently with Task3 schema in a separate C: worktree after Task2 metadata contracts passed review — their code responsibilities are independent on the frozen native models, and isolation avoids shared mutable files — cost if wrong: additive registration/model conflicts or cross-writer assumptions require integration fixes and tests before Task7. Task4 owns codec/source projection, Task3 owns DDL and preflight gates; final combined review remains required.

7. Explicitly block legacy ANSI_PADDING/ANSI_NULLS metadata that supported target engines cannot recreate faithfully, after primary-source confirmation — silently emitting ineffective SET options would claim fidelity not provided — cost if wrong: some otherwise exportable legacy tables are conservatively refused until a tested compatibility path is added. Only explicit facts and affected native types trigger the gate.

8. Treat rare over-budget legal identifier lists as bounded metadata, using a separate narrowly scoped metadata-only statement path while preserving value-bearing statement and row-buffer budgets — SQL Server's maximum column count and identifier length impose a fixed bound independent of row payload, whereas rejecting legal tables would turn algorithm budgets into data limits — cost if wrong: an unusually wide-name table can consume more bounded metadata memory or reveal importer statement limits; add a pathological-name regression and keep the 4 MiB batch ceiling.

9. After Task7 passes review, run Task10's engine/service live acceptance in an isolated C: worktree alongside Tasks8–9 native UI/routing — the final writers/artifact/service contracts are then stable, and DB fixtures and UI files have separate ownership — cost if wrong: shared test registration or a discovered engine defect may require an additive merge or coordinated fix; final combined builds/smoke and relevant reruns remain mandatory after integration. Task10 must not claim unimplemented UI/routing acceptance.

10. Present ETA as the currently measurable phase's remaining time, and leave unmeasured future phases explicit — source-read throughput cannot truthfully predict future disk verification or remote mirror throughput — cost if wrong: users get a less complete total-finish forecast; label it 本階段預估 / Phase ETA and never imply whole-job completion from that value. Overall estimated percent still includes all required phases and never reaches100 before complete.

11. Permit an isolated, official portable Microsoft sqlcmd client under the authorized C: fixture, without installing or replacing the system client — classic15.0.1300.359 actually truncates a valid statement crossing byte2147483648 — cost if wrong: client-specific import compatibility must be documented and validated; a newer downloaded client is checked for official release hash and Authenticode, with no AV bypass.

12. For Go sqlcmd, validate native UTF-8 input and use its supported equivalent command instead of requiring the classic-only -f65001 switch — the binding contract is UTF-8, variable substitution disabled, fail-on-error and one session, not an unsupported flag spelling — cost if wrong: non-ASCII metadata or client parsing could differ; require native Unicode/parser/temp-session probes and full large restore before acceptance. Preserve classic client FAIL evidence.

13. Retain this plan's ignored SDD workspace as local operational evidence until the authorized fixture is retired — the acceptance runner intentionally consumes its fixture-environment.json authorization manifest, so deleting the workspace would break repeatable isolated verification — cost if wrong: untracked local reports remain and require later explicit cleanup; none are published, no raw bulk artifact is added to Git. Public rulings and final verification still live in Git.
