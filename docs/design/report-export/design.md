# 匯出報表精靈：畫面設計紀錄

日期：2026-10-06\
狀態：先看畫面；本文件記錄本輪原型與樣本的設計範圍，不是程式實作計畫。

## 範圍與入口

- 目標為 Windows WinForms 完整版，在資料庫節點的右鍵選單新增「匯出報表…」。
- 報表內容為資料庫結構，包括選取的資料表、欄位、型別、NULL、主鍵、預設值、註解，以及模板適用的索引與 DDL；不輸出業務資料列，也不擷取實際資料當範例。
- 保留既有「產生資料字典」入口及其 HTML 匯出流程；本輪不替換它，也不改變既有自動作業契約。
- 本輪以固定示範 schema 展示精靈畫面、六種模板縮圖與可開啟的實際範例檔。範例內容清楚標示為示範資料庫。
- 本輪不增加新套件、不實作匯出器，也不執行真實資料庫操作。

## 三步精靈

### 1. 選擇資料表

- 頂端顯示資料庫名稱及「資料庫結構報表」說明，避免誤認為業務資料匯出。
- 資料表以核取清單呈現，預設全選；提供搜尋、全選與全部取消，以及「已選 X / 共 Y 張」摘要。
- 搜尋只影響目前顯示的清單，不隱含取消看不見的已選資料表；全選與全部取消明確作用於全部資料表。
- 零選取時停用「下一步」，並在清單旁顯示「請至少選擇一張資料表」。
- 本輪選取單位為 table，不把 view 或 collection 默認併入；其他物件種類的支援留待後續確認。

### 2. 選擇格式與模板

- 格式為 DOCX、Excel（.xlsx）與 PDF。切換格式後，中央顯示該格式的兩張模板卡片。
- 每張卡片包含模板名稱、可辨識的版面縮圖、簡短適用情境，以及「開啟範例」操作。
- 模板縮圖必須與該模板的實際範例檔相符；範例使用同一份示範 schema，方便比較排版與資訊密度。
- 縮圖可放大預覽；開啟範例屬於預覽動作，不會修改精靈已選項目或直接產生使用者報表。
- 選取狀態用邊框、核取標記及文字共同表示；每個格式預設選取第一個模板。返回上一步後保留使用者選擇。

| 格式 | 模板 | 版面與內容方向 |
| --- | --- | --- |
| DOCX | 經典資料字典 | 標題、資料庫摘要、逐表章節與欄位表格；以日常技術文件閱讀與後續編修為主。 |
| DOCX | 專案交付文件 | 封面、文件資訊、目錄與逐表章節；以可交付的文件層次呈現結構資訊。 |
| XLSX | 一表一工作表 | 每張資料表各自的欄位工作表；強調分表檢閱，首頁索引可於後續模板擴充。 |
| XLSX | 欄位總覽清冊 | 將全部選取資料表的欄位集中列出，保留資料表名稱欄；方便篩選、比較與補註。 |
| PDF | 標準結構手冊 | 封面摘要、清楚的逐表章節、頁碼與閱讀導覽；適合固定版面分享。 |
| PDF | 精簡審閱版 | 精簡首頁、緊湊欄位表格與必要結構資訊；降低頁數，適合快速審閱。 |

### 3. 確認輸出

- 摘要列出資料庫、選取資料表數、格式、模板、輸出檔名與路徑，並保留返回修改的操作。
- 顯示文件標題與作者等文件資訊；樣本提供具體示例，但不自動挾帶帳號、密碼或連線字串。
- 使用者選定目的地後才啟用「開始匯出」；遇到同名檔案時明確確認是否覆寫，取消確認仍留在本步。
- 成功後顯示「開啟檔案」、「開啟資料夾」與「完成」。進度畫面中途不顯示成功操作。

## Punky 與匯出狀態

- Punky 作為陪伴與狀態提示，沿用專案現有角色參考圖；不遮住進度、錯誤原因與取消操作，也不以動畫作為唯一狀態訊號。
- 正式介面需涵蓋進行中、取消中、已取消、失敗及成功。本輪原型已展示進行中、取消及示範完成；失敗與真正等待取消的流程留待實作。示範進度明示為模擬，不宣稱由真實匯出計算。
- 執行過程依序呈現「收集結構資料 → 排版產生文件 → 寫入並驗證輸出檔」。
- 收集階段可顯示已完成／總資料表數及目前資料表；排版與寫入階段沒有可靠分母時使用不定進度或階段狀態，不推算假的剩餘時間，也不顯示假的精確百分比。
- 只有 metadata 收集、文件產生、檔案落地與輸出驗證都完成，才顯示 100% 及成功；request 或背景工作結束本身不等於檔案成功。
- 「取消」切換為「正在取消」，待工作真正停止後顯示已取消。取消前不宣稱清理完成，也不將部分輸出標示為成功檔案。
- 失敗畫面保留選取項目與目標路徑，顯示失敗階段、可理解的原因與重試／返回選項；若只有部分資料表取得 metadata，不得靜默顯示完整成功。
- 匯出中停用會重複啟動工作的按鈕；完成、失敗或取消後恢復適合該狀態的操作。

## 模板識別與後續範圍

模板名稱供畫面顯示，未來可由小型 template catalog 使用穩定 ID 對應格式、名稱、縮圖與範例。此處僅約定識別方式，不建立外掛平台、遠端模板市場或設計器。

| 建議穩定 ID | 格式 | 顯示名稱 |
| --- | --- | --- |
| `docx.classic-dictionary` | DOCX | 經典資料字典 |
| `docx.project-handover` | DOCX | 專案交付文件 |
| `xlsx.table-sheets` | XLSX | 一表一工作表 |
| `xlsx.column-inventory` | XLSX | 欄位總覽清冊 |
| `pdf.structure-handbook` | PDF | 標準結構手冊 |
| `pdf.compact-review` | PDF | 精簡審閱版 |

ID 不依賴翻譯文字或畫面排序；後續增加模板時追加項目，不把現有 ID 改成不同含義。以上為設計約定，尚未增加 catalog 程式碼。

## 現有程式接點與限制

- `mySQLPunk/Form1.cs`：`BuildTreeContextMenu()` 將資料庫節點導向 `AddDatabaseNodeMenuItems()`；此處是新增「匯出報表」入口的接點。
- `GenerateDataDictionaryForNode()`：現有流程為選項視窗 → HTML 存檔位置 → `DataDictionaryService.BuildHtml()`。它目前同步取得 metadata，原註解明確說明同一條連線不能由兩個執行緒搶用；後續若加入背景進度，不可直接把共用連線丟到 `Task.Run` 並容許其他操作並行。
- `mySQLPunk/lib/DataDictionaryService.cs`：已有標題、作者、主色、模板與章節選項，並透過 `IDatabase` 取得資料表、欄位、索引與 DDL；目前 metadata 讀取與 HTML 排版仍在同一流程，沒有報表進度或取消契約。
- `mySQLPunk/lib/SchemaModelService.cs`：`SchemaModelSnapshot` 已整理 table、column、PK 與 FK，可參考其跨 provider 正規化方式；目前缺少註解、預設值與完整 DDL，不能直接當作完整結構報表內容。
- `mySQLPunk/lib/QueryResultExportService.cs`：現有 XLSX 為 ZIP/XML 輸出，資料來源是一個 `DataTable`、一張工作表；可參考編碼與 Excel 限制處理，但不是本次多模板報表匯出器。來源與套件宣告中未找到現成 DOCX 或 PDF 匯出器；既有資料字典的 PDF 是由瀏覽器列印另存。
- `mySQLPunk/RunnerProgressOverlay.cs` 與 `mySQLPunk/AnimatedRunnerProgressBar.cs`：已有動畫進度控制項與 `(current, total, message)` 顯示方式，可作為後續 WinForms 介面參考。
- Punky 現有參考素材為 `snapshot/mySQLPunk_avatar.png`、`snapshot/mySQLPunk_avatar_wink.mp4` 與 `mySQLPunk/image/mySQLPunk_avatar_wink.gif`，授權說明在 `mySQLPunk/image/ASSET_NOTICES.md`。本次在來源與文件中未找到可核實的固定角色圖像生成 prompt；聊天助理的 system prompt 不是圖像外觀規格。

## 本輪驗證邊界

本輪交付範圍只有示範原型、模板縮圖與範例檔，供使用者先確認流程與版面。範例檔產生及開啟檢查不代表 WinForms 匯出功能已完成。

本輪未修改 C# 程式、未新增正式匯出入口、未連接真實 DB，也未驗證真實 metadata、共享連線執行、背景取消、實際覆寫或大型資料庫的匯出結果。DOCX／XLSX／PDF 在使用者實際閱讀工具中的顯示與列印結果，應與本輪原型的本機檢查分開記錄。
